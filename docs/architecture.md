# Architecture and expanded agreed contract

The model helps developers and technical/solution architects prepare and review Java/Spring API changes consumed by React/TypeScript or Angular. It connects architectural rules, dependency impact, selected quality and supplied business criteria to source evidence. It is an independent deterministic module; the call's subjective 7/10 estimate is not measured efficacy.

## Decisions and rationale

- Node 24 ESM, TypeScript 5.9.3 Compiler API and java-parser 3.0.1 CST preserve the proven parsers. The typed workspace compiles to app-dist; the small browser uses local plain JS/SVG/CSS without AI/models or external assets. The shared typed **file** graph retains declaration evidence without claiming semantic dataflow.
- One acquired snapshot feeds parser/graph/declaration/rule/quality/requirement stages. Every fact retains project/path/range/originalrevision/hash/excerpt. No guessed links are emitted. Mutable directories are not reread for contradictory stage provenance; concurrent acquisition is still non-atomic.
- Consumer-to-dependency edges retain baseline/candidate phases. Literal HTTP and conservative Java receiver matching are medium certainty; relative imports/lexical facts may be high. Indirect representative chains are low, depth 12/cycle bounded with alternate/deeper incompleteness explicit. Import-only file edits remain selectable.
- Multi-project configuration names source roots, repository/module labels and owned/versioned cross-project mappings. Monorepo directory modules and separate repositories share the engine. Explicit HTTP/package-source assertions do not verify deployment, build resolution or runtime. Renamed equivalent fixtures prevent application-name recognition criteria.
- Architecture stays advisory, data-only and owned/versioned. Forbidden-import and endpoint-contract-change classify new/pre-existing/worsened/resolved and distinguish policy changes. Examples/exceptions are proposed or supplied assertions, never authenticated approval. Optional example and reviewed-exception expiry use asOf; stale source pins/ranges stay visible.
- Trusted ESLint 10.12.0/typescript-eslint 8.71.1 runs in memory; jscpd 4.0.5 and PMD 7.17.0 use temporary source copies and application-owned configuration. Examined project configs/builds/tests/plugins are not loaded. Partial coverage prevents false resolved claims. Selected syntactic null/resource/async, duplication/complexity and SOLID-related signals are review evidence, not universal safety/design proofs.
- Requirements accept literal structured checklists with explicit user confirmation. Drafts remain unverified. Criteria combine code/test selectors across projects with original provenance, missing edges and potential mismatch. Comments can match. No matched text implies executed tests, runtime compliance, completeness or authenticated confirmation. Matching has bounded work budgets.
- Docker packages runtime dependencies, Java/PMD and built UI into Linux amd64. Compose uses nonroot/read-only filesystem/source mounts, disposable tmp/cache and loopback port. The Windows bundle needs Docker Desktop only. CloudQA is separate from unrun Windows-host acceptance. Image ID/archive hash pin the actual build; later Debian-index-based builds need not be byte-identical.
- Cache keys include exact source/revision/root/exclusions, rules/priorrules/date/task and analyzer/build/lock identity. Dirty worktrees bypass report/quality cache. Quality adds actual trusted tool scripts/jars/versions/config. Mappings rebuild the graph; checklists reevaluate. Digest envelopes detect corruption, not hostile authentication. Destinations are canonicalized outside examined roots.
- Git reads disable hooks/fsmonitor, lazy fetch/transports/prompts, replace refs and optional locks. Only the explicitly selected canonical root is trusted through safe.directory. All modes consistently exclude generated/vendor sources and symlinks. Missing objects fail instead of fetching or executing transports. Immutable commits offer strongest repeatability.

These are pragmatic reversible POC decisions. Selected analyzers and ordinary browser assets support dependable demonstrations without a broad plugin framework. Large-repository scheduling, complete semantic resolution and execution-aware dataflow remain future work.

## Scope and governance

Expanded authorization includes the visible model, built Windows Docker bundle and tested source publication to the dedicated review-analysis repository. External AI, private-computer access, unrelated repositories/recovery work, PR messages, force push, merge and deployment remain excluded. The review branch preserves main history and README content. Parent coordination owns the private project record/main-chat delivery.
