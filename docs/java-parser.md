# Java CST adapter

`src/java.js` exports pure `parseJava(path, text)` and uses the pinned `java-parser@3.0.1` CST. It does no filesystem or network work. Output follows `parser-contract.md`; comments and string contents cannot masquerade as declarations or calls. Parser diagnostics return an empty analysis with an explicit unknown and at most 1,600 diagnostic characters.

## Supported contracts and references

- Package-qualified named classes, interfaces, records, enums, and annotation types; nested named member types retain their qualified owner.
- Method/constructor signatures, annotation text, generic and parameter text, DTO fields, interface constants, and record components. Declaration bodies contain the original complete source declaration, and inclusive line ranges include modifiers/annotations. Fields declared together retain their full shared source range/body while each has its own signature and key.
- Class keys are qualified names. Fields/components use `owner#name`; methods use `owner#name/arity`; constructors use `owner#<init>/arity`. Same-owner/name/arity overload collisions receive a `(parameterType,...)` suffix. An ordinary parameter-type change keeps the method key stable, permitting contract comparison. Method declarations additionally record integer `arity` and a `varargs` flag; engine call matching uses exact integers, not key prefixes.
- Explicit imports and CST type references. Import bindings and same-file lexical types can carry `target`; ambiguous imports and generic type variables do not acquire guessed targets.
- Method invocations use CST argument lists for arity. Parameters, explicit local declarations, fields, and current-instance calls supply receiver information. Block, initializer, loop, resource, catch, and lambda shadow scopes prevent a name from incorrectly retaining an outer field type. Generic parameters, arrays, varargs, `var`, lambda parameter inference, and chained expression results have no inferred receiver type. Calls with unsupported receivers are `dynamic` and have explicit unknowns. Only unique lexically declared current-instance methods have parser-level call targets; the analysis engine handles cross-file candidates.
- Verified Spring `RequestMapping`, `GetMapping`, `PostMapping`, `PutMapping`, `DeleteMapping`, and `PatchMapping`: fully qualified annotations, explicit imports, or a sole Spring annotation package wildcard import. Literal `path`/`value` strings and arrays combine class/method routes. String escapes, including Unicode and octal escapes, are decoded. URI template segments such as `{id}` remain symbolic.
- `RequestMapping.method` supports the verified Spring `RequestMethod` enum, fully qualified values, explicit imports, and verified static enum imports. Empty/omitted method arrays are represented by `*` (no declared restriction). Explicit class/method method sets combine by union, following [Spring's request-method condition implementation](https://raw.githubusercontent.com/spring-projects/spring-framework/v6.2.0/spring-webmvc/src/main/java/org/springframework/web/servlet/mvc/condition/RequestMethodsRequestCondition.java). Empty path arrays use the empty path default, following [Spring's path condition implementation](https://raw.githubusercontent.com/spring-projects/spring-framework/v6.2.0/spring-webmvc/src/main/java/org/springframework/web/servlet/mvc/condition/PatternsRequestCondition.java).

## Deliberate limitations

This is syntactic contract extraction, not compilation or a complete Java/Spring symbol resolver. Parsing does not validate Java types or annotation applicability. The pinned parser throws its first error; it does not recover partial declarations. Java Unicode preprocessing outside string literals is not implemented by the underlying parser.

Local types and anonymous class members (including enum-constant class bodies) produce explicit unknowns and do not merge into the containing named class. Annotation element methods and enum constants are not separate contracts. Compact record constructors have implicit parameters and an explicit limitation. Synthesized record accessors, generated/Lombok members, inheritance/overrides, generic bounds/substitution, overload argument typing, reflection, static import method resolution, method references, and runtime dispatch are not resolved. Constructors are declarations and instantiated types are references; constructor invocation edges are not emitted. Primitive types do not create class dependency references.

Spring constants/concatenation/ternary expressions, parenthesized routes, text-block routes, `${...}`/`#{...}` configuration, custom/meta/composed annotations, inherited controller mappings, multiple mapping annotations, and simultaneous `path`/`value` aliases remain unknown rather than guessed endpoints. Qualifiers such as `params`, `headers`, `consumes`, and `produces` generate unknowns even when a literal route can be emitted. Wildcard class paths combined with nonempty method paths remain unknown because [Spring's path-pattern combination](https://raw.githubusercontent.com/spring-projects/spring-framework/v6.2.0/spring-web/src/main/java/org/springframework/web/util/pattern/PathPattern.java) is not simple string concatenation. Emitted HTTP methods describe configured annotation verbs; implicit HEAD/OPTIONS and runtime matching semantics are not expanded. Template route matching is left to the engine; regex-constrained URI templates remain explicit unsupported-route-constraint unknowns. Recognized varargs candidates and explicit inheritance receiver cases remain unresolved at engine call resolution rather than selecting a potentially incompatible overload.

Every unsupported receiver, generic reference, recognized unresolved mapping, wildcard import, method reference, parse failure, or excluded class context carries an explicit unknown where detectable. Unresolved named type references retain their source names for the engine; absence of a target is not proof of absence of a dependency.

Validation: `node --test test/java.test.js` covers contracts/ranges, overloads, route arrays and class prefixes, method-set union/defaults, Java escapes, comment/string isolation, dynamic routes, receiver scopes, generic/varargs/lambda shadows, local/anonymous class exclusion, and bounded diagnostics.
